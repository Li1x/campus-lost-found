> **版本**：v1.0  
> **日期**：2026-10-16  
> **状态**：已确认

---

## 1. 项目概述

### 1.1 项目背景

校园内学生日常丢失物品频繁，传统的线下公告栏效率低、覆盖面窄。本系统旨在提供一个线上平台，帮助学生快速发布失物和招领信息，提高物品归还效率。

### 1.2 项目目标

- 为学生提供发布失物/招领信息的便捷平台
- 实现规范的认领流程，确保物品安全归还
- 管理员审核机制保障信息真实性
- 站内消息通知确保流程及时推进

### 1.3 技术栈

| 层级 | 技术选型 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router + Axios |
| 后端 | Java + Spring Boot + Maven + MyBatis-Plus |
| 数据库 | MySQL（数据库名：`campus_lost_found`） |
| 架构 | 前后端分离，后端提供 RESTful JSON API |

## 3. 功能模块

### 3.1 认证模块

#### 3.1.1 学生注册
- 输入：学号、用户名、密码、确认密码
- 规则：学号唯一；密码至少 6 位，包含字母和数字
- 密码存储：BCrypt 加密

#### 3.1.2 登录
- 输入：学号 + 密码
- 输出：JWT Token（有效期 24 小时）+ Refresh Token
- 登录失败超过 5 次锁定 30 分钟

#### 3.1.3 登出
- 清除客户端 Token

### 3.2 用户管理模块

#### 3.2.1 个人资料
- 可编辑字段：昵称、头像、手机号、邮箱、QQ/微信
- 头像：支持上传，限制 2MB，格式 jpg/png/webp
- 密码修改：需验证旧密码

#### 3.2.2 用户管理（超级管理员）
- 查看所有用户列表（分页+搜索）
- 禁用/启用用户账号
- 创建管理员账号
- 重置用户密码

### 3.3 物品分类模块

#### 3.3.1 预置分类

| 序号 | 分类名称 | 图标（建议） |
|---|---|---|
| 1 | 证件 | 🪪 |
| 2 | 电子设备 | 📱 |
| 3 | 书籍文具 | 📚 |
| 4 | 衣物饰品 | 👕 |
| 5 | 钥匙卡片 | 🔑 |
| 6 | 运动器材 | ⚽ |
| 7 | 生活用品 | 🧴 |
| 8 | 其他 | 📦 |

#### 3.3.2 分类管理（管理员）
- 增删改查分类
- 调整分类排序
- 启用/禁用分类

### 3.4 失物发布模块

#### 3.4.1 发布失物
- 必填字段：物品名称、分类、丢失地点、丢失时间（精确到日）、描述
- 可选字段：图片（最多 3 张，单张 ≤ 5MB）、联系方式
- 发布后状态为 `PENDING`，等待管理员审核

#### 3.4.2 编辑失物
- 仅发布者可编辑
- 仅 `PENDING` 或 `REJECTED` 状态可编辑
- 编辑后状态重置为 `PENDING`

#### 3.4.3 搜索失物
- 支持关键词搜索（标题 + 描述模糊匹配）
- 支持按分类、地点、时间范围、状态筛选
- 分页展示，默认按时间倒序
- 游客和普通用户仅能搜索 `APPROVED` 状态的物品

### 3.5 招领发布模块

#### 3.5.1 发布招领
- 必填字段：物品名称、分类、拾得地点、拾得时间、描述、当前存放位置
- 可选字段：图片（最多 3 张，单张 ≤ 5MB）、联系方式
- 发布后状态为 `PENDING`

#### 3.5.2 其他功能
- 编辑、搜索规则与失物模块一致

### 3.6 认领申请模块

#### 3.6.1 发起认领
- 前提：物品状态为 `APPROVED`
- 限制：不能认领自己发布的物品
- 输入：认领说明（证明自己是失主/拾得者的描述）、联系方式
- 同一用户对同一物品不可重复申请（已有 PENDING/OWNER_APPROVED 状态时）

#### 3.6.2 认领审核流程（双重确认）

```
认领人提交 → PENDING
    ↓
物品发布者确认 → OWNER_APPROVED / OWNER_REJECTED
    ↓
管理员最终审核 → APPROVED / REJECTED
    ↓
认领成功 → 物品状态变为 CLAIMED
```

- **第一步**：物品发布者查看认领申请，确认或拒绝
- **第二步**：发布者确认后（`OWNER_APPROVED`），管理员进行最终审核
- 管理员可以直接拒绝任何状态的认领申请
- 同一物品同时只能有一个 `APPROVED` 的认领

#### 3.6.3 认领完成
- 认领审核通过后，物品状态变为 `CLAIMED`
- 发布者可将物品标记为 `COMPLETED`（交接完成）

### 3.7 管理员审核模块

#### 3.7.1 内容审核
- 审核对象：失物发布、招领发布
- 审核操作：通过（`APPROVED`）/ 拒绝（`REJECTED`）+ 审核意见
- 记录审核人、审核时间

#### 3.7.2 认领审核
- 审核已被发布者确认（`OWNER_APPROVED`）的认领申请
- 操作：通过 / 拒绝 + 审核意见

#### 3.7.3 审核日志
- 所有审核操作记录到操作日志表
- 包含：操作人、操作类型、目标对象、操作时间、备注

### 3.8 站内消息模块

#### 3.8.1 消息类型

| 类型 | 触发场景 | 接收者 |
|---|---|---|
| 审核结果 | 物品审核通过/拒绝 | 发布者 |
| 认领通知 | 有人发起认领 | 物品发布者 |
| 发布者确认结果 | 发布者确认/拒绝认领 | 认领人 |
| 认领审核结果 | 管理员审核认领通过/拒绝 | 认领人 + 发布者 |
| 系统通知 | 物品过期等 | 相关用户 |

#### 3.8.2 消息功能
- 消息列表（分页、未读优先）
- 标记已读 / 全部已读
- 导航栏未读消息数角标

### 3.9 统计面板模块（管理员）

#### 3.9.1 统计指标

| 指标 | 说明 |
|---|---|
| 用户总数 | 注册用户总数 |
| 今日新增用户 | 当天注册数 |
| 物品总数 | 失物 + 招领总数 |
| 待审核数 | 当前待审核的物品和认领申请数 |
| 已完成认领数 | 状态为 COMPLETED 的物品数 |
| 认领成功率 | 已完成 / 已审核通过 |
| 近7天趋势 | 每日发布数折线图 |
| 分类分布 | 饼图展示各分类占比 |

## 4. 状态流转

### 4.1 物品状态

| 状态 | 标识 | 说明 |
|---|---|---|
| 待审核 | `PENDING` | 用户刚发布或修改后重新提交 |
| 已通过 | `APPROVED` | 管理员审核通过，可被搜索和认领 |
| 已拒绝 | `REJECTED` | 管理员审核拒绝，用户可修改后重新提交 |
| 已认领 | `CLAIMED` | 认领申请通过 |
| 已完成 | `COMPLETED` | 物品已成功交还 |
| 已关闭 | `CLOSED` | 发布者主动关闭 |
| 已过期 | `EXPIRED` | 超过 30 天未被认领，系统自动标记 |

### 4.2 认领状态

| 状态 | 标识 | 说明 |
|---|---|---|
| 待确认 | `PENDING` | 认领人已提交，等待发布者确认 |
| 发布者已确认 | `OWNER_APPROVED` | 发布者确认，等待管理员最终审核 |
| 发布者已拒绝 | `OWNER_REJECTED` | 发布者拒绝 |
| 已通过 | `APPROVED` | 管理员审核通过 |
| 已拒绝 | `REJECTED` | 管理员审核拒绝 |
| 已取消 | `CANCELLED` | 认领人主动取消 |

## 5. 非功能性需求

### 5.1 安全

- JWT Token 认证 + Refresh Token 刷新
- 服务端 RBAC 权限控制，不依赖前端路由守卫
- 密码 BCrypt 加密存储
- 输入参数校验与过滤（防 XSS）
- MyBatis-Plus 参数化查询（防 SQL 注入）
- CORS 跨域配置
- 文件上传白名单校验 + 大小限制
- 联系方式仅物品相关方和管理员可见
- 日志中不记录密码、Token、私人联系方式

### 5.2 性能

- 列表查询使用分页，默认每页 10 条
- 图片懒加载
- 数据库索引优化（user_id、category_id、status、created_at）

### 5.3 可用性

- 响应式布局，适配桌面和平板
- 操作反馈：加载状态、空状态、成功/错误提示
- 破坏性操作二次确认
- 表单实时校验

### 5.4 数据

- 关键数据逻辑删除（用户、物品）
- 数据库变更通过 SQL 迁移脚本管理
- 审核操作记录到操作日志

## 6. 约束与假设

### 6.1 约束

- 不实现站外推送（邮件/短信），仅站内消息
- 不实现实时聊天功能
- 不实现移动端 App（仅 Web）
- 文件存储使用本地磁盘（不上云存储）

### 6.2 假设

- 学号在校内唯一
- 管理员通过超级管理员手动创建
- 系统部署在校园内网或有网络访问权限的环境
